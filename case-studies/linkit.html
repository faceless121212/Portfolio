Side project

Linkit: replacing a content spreadsheet with a planning app

  • LinksSide project · GitHub
  • RoleFounder-PM and builder (solo, AI-assisted)
  • TimelineOct 2026
  • LocationRemote

TL;DR

Problem
Planning X posts in a spreadsheet meant losing track of what was an idea, a draft, scheduled or published, and missing planned posts.
My role
Defined the scope and built it with Claude. I'm also its first user.
Team
Solo, with AI.
Outcome
I now use it for my own posts, and posting is more consistent. It has an editor with an X-accurate character count, a Kanban board, a calendar, reminders, a daily digest and a streak.

Context and why it mattered

I post mostly on X. The spreadsheet worked until it didn't: no reminders, no status at a glance, and no link back to the published post.

Hypotheses and prioritization

Hypothesis: reminders plus a visible pipeline (Idea → Draft → Scheduled → Published) will make posting more consistent than a spreadsheet.

What I said no to: posting to X automatically, or using the X API at all. You post by hand and paste the URL back. That keeps the product free of API costs and platform risk.

Experiments and execution

  • Character counter weighted like X's (URLs count as 23, emoji as 2), thread mode and autosave.
  • Status rules on the board: moving a post to Scheduled asks for a date, Published asks for the URL, and leaving Published asks for confirmation.
  • Reminders before each scheduled post, a daily digest of today's and overdue posts, and a publishing streak.

Results

More consistent posting since I switched from the spreadsheet.

What I learned

Being your own first user is the fastest feedback loop. Every rule on the board came from a real moment where the spreadsheet failed me.
